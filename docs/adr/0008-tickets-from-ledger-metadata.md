# 票只看账本里写的元数据，界面不联网查时刻

火车票交易写齐 `train`、`from`、`to`、`depart` 四项元数据才画成车票，缺一项就照普通交易显示，不从摘要里猜车次和站名。
到站时刻、座位、手续费也只从元数据读。

考虑过界面联网查时刻表，没做：12306 没有公开接口，查到的也不会写回账本，同一张票每次打开都要再查一遍。
改成记账时由 AI 查好写进账本，账本就是唯一的数据来源，离线也能看。

退票照抄原票的元数据，金额是退回的钱，界面按金额方向判断是退票；手续费写在 `fee:` 上，原票 = 退回 + 手续费。
机票将来用同一套元数据，`train` 换成 `flight`。

门票沿用同一条：写齐 `attraction`、`visit` 才画成门票，退票和手续费的规则也一样。
门票有专门的科目 `Expenses:Travel:Attractions`，考虑过凡是记在这个科目的都画成门票，没这么做：
门票最有用的是入园日期（多半提前买，付款日不是去玩的日子），这只有元数据给得出；
导入的旧账大多没有景区名和日期，按科目画出来是空票。景区名也不拿收付方顶替，平台买的票收付方是携程、美团。
